# 多模态：从图片里读场景

需求往往没有文字，只来一张 Figma 截图、原型图、或画满箭头的业务流程图。以前要人先"翻译"成文字再写用例，等于多做一遍工。现在把图直接丢进来，用多模态能力读取。

**核心观点：图片和文字可以同时放进去，交叉对照，补全单独依赖任一方都可能漏掉的场景。**

---

## 识别映射（按图类型）

| 输入类型 | 识别内容 | 产出用例类型 |
| --- | --- | --- |
| UI 设计稿 | 页面元素、输入框、按钮、状态文案、校验提示 | 表单验证用例 + 交互用例 |
| 流程图 | 分支条件、步骤顺序、异常路径、起点/终点 | 完整场景流用例（基本/备选/异常流） |
| 规则表格截图 | 枚举值、条件组合、阈值 | 等价类 + 边界值用例 |

## 读图要点

- **UI 设计稿**：识别每个输入框的 `maxlength` / `placeholder` / 必填星号 / 错误态文案 → 生成"超长 / 空 / 格式错误 / 必填校验"用例；识别按钮的禁用 / loading 态 → 生成"重复点击防抖""提交中不可重复提交"用例。
- **流程图**：沿每条分支走一遍，基本流一条、每个判断节点的 True/False 各一条、异常回退一条；识别"超时 / 失败重试 / 取消"节点。
- **规则表**：把枚举列拆成等价类，把阈值列拆成边界值（上点/离点）。

## 交叉对照（图片 + 文字同时给）

把图识别结果和 PRD 文字比对，补全任一方单独都可能漏的场景：

- PRD 说"支持中文昵称"，图里输入框 `maxlength=20` → 补"21 位中文"边界用例。
- 图里有"提交中"loading 态但 PRD 未提 → 补"重复点击防抖"用例。
- PRD 列了状态枚举 {待支付, 已支付, 已取消}，图里还有"已退款" → 补退款场景。

## 输出约定

- 从图识别出的元素写入 **"隐含需求假设"清单**。
- 无法 100% 确认的业务规则标 `[假设]`（如"按钮点击后是否弹确认框"），交用户确认——这是质量预审的**检查点②之一**。
- 图片中读到的需求也应进入 Step 1 的**需求规则清单**（与 XMind / PRD 抽取结果合并），参与后续覆盖率统计与预审。

## 执行方式

1. 运行 `scripts/read_ui_image.py <image> -o ui_elements.json` 校验图片格式并输出元素抽取骨架。
2. Agent 使用视觉能力读取图片，填充 `detected` 列表（页面元素 / 输入框 / 按钮 / 状态 / 约束）。
3. 按上表映射生成 `ui_cases.json`；无法确认的规则标 `[假设]`，并与 PRD / XMind 文字交叉对照。
4. 将图片中识别出的需求规则合并到 Step 1 的 `requirements.json`，参与覆盖率统计。
