# 测试用例流程排序

## 1. Overview

把散乱的用例集合还原成「能照着跑」的执行清单。

排序依据是**业务执行链路 + 测试点依赖**，不是 ID、拼音、字母序、导入时间，也**不是优先级或测试类型**。

```
L0 分类 partition   公共 → 横屏专项 → 竖屏专项（或 公共 → BB2 → BB3）
 └ L1 顶级模块    APP → 嵌入式固件 → 联调功能 → 系统后台（端视角，默认在模块内聚块）
     └ L2 功能模块  APP-启动 → 登录 → 手机号 → 协议书 → 验证码 → …
         └ L3 测试点  模块内的界面/子流程节点（进入 → 主流程 → 交互 → 校验 → 异常 → 适配）
             └ L4 组内次序  显式序号 > 类型序（可选）> 优先级序（可选）> 原始顺序
```

**只改行顺序，不改内容**：单元格值、样式、行高、超链接、批注随行搬迁；多 Sheet 一次处理。

## 2. 策略来源与实证依据

本策略从《测试用例管理.xlsx》（EQi 智能出行，1278 条 / 4 顶级模块 / 19 功能模块 / 23 列）反推得出。三条关键实证：

| 观察 | 数据 | 结论 |
|------|------|------|
| 模块内测试类型是否聚块 | `APP-验证码` 58 条中类型切换 21 次；`APP-注册` 35 条切换 15 次 | **类型不是模块内的分组依据** |
| 模块内优先级是否单调 | 各模块 `P0/P1/P2/P3/P4` 混排，无单调段 | **优先级不是排序主轴** |
| 模块自身的排列 | 启动→登录→手机号→协议书→验证码→重置密码→注册→邮箱→注销→配对→设备设置→OTA→版本更新→个人中心 | **主线是用户使用链路与页面层级** |

特例：`APP-版本更新` 112 条仅 1 次类型切换（主流程测试 → 模块功能测试），说明该模块作者做了类型分层 —— 因此本 Skill 保留 `sort_by_type` 开关，但**默认关闭**，按需对该模块开启。

由此确立的基本原则：

1. **两级模块分组**：先分端（顶级功能模块），再分功能模块。
2. **测试点驱动**：模块内以「界面/子流程节点」为测试点，一个测试点内允许混排功能、UI、文字查验等类型。
3. **保序优先**：规则没覆盖到的用例，承接上一个测试点、保持原相对位置 —— 因为原库顺序本身承载了测试点逻辑。
4. **属性不越权**：类型、优先级、设备型号、测试状态都是「属性」，只有显式开启才参与排序。

## 3. When to use / not to use

**适用**
- 用例按 ID/拼音/录入时间散乱，需要还原可执行顺序。
- 三分类库（公共/横屏专项/竖屏专项）或多机型库（公共/BB2/BB3）需要按形态集中执行。
- 手工维护的用例库要补排序，但作者已在模块内按测试点写好顺序（**保序策略最贴合**）。
- 需要一份可核对的排序依据（分类/阶段/模块/测试点 + 条数）。

**不适用**
- 增删列、改写用例内容、生成新字段（用其他工具）。
- 纯按优先级筛选或重排（本 Skill 不默认按优先级排序）。

## 4. 判定优先级（Resolution Order）

当一个用例可能落入多个分组时，按以下**固定优先级**判定，不可越级：

| 级别 | 判定项 | 规则 |
|------|--------|------|
| **R1** | 分类分区 `partition` | 按 `partition.order` 定位分区；值不在 order 中 → 排该维度末尾；空值 → 取 `partition.default`。分区是最外层，不可被后续规则覆盖 |
| **R2** | 功能模块 `module` | `module_sequence` **精确匹配优先**；未精确命中时用**最长前缀匹配**（`设备端-启动` 归 `设备端`）；都未命中 → 排模块维度末尾（不丢数据） |
| **R3** | 顶级模块 `top_module` | `top_module_mode=sub` 时在同一功能模块内聚块（默认）；`group` 时提升到模块之前；`weak` 时不参与排序键 |
| **R4** | 测试点 `testpoint` | 规则按 `rule.priority` **升序**试匹配，同 `priority` 按**声明顺序**；`exclude` 命中即否决当前规则；命中第一条即止 |
| **R5** | 未命中兜底 | 默认 **承接上一个测试点**（`anchor + 0.4`，保持原相对位置）；仅 `fallback="tail"` 的模块才排到末尾 |
| **R6** | 组内次序 | 显式序号列 → 测试类型序（仅 `sort_by_type`）→ 优先级序（仅 `sort_by_priority`）→ **原始行号**（稳定兜底） |

两条常被误解的约束：

- **`rule.priority` 只决定「谁先匹配」，不决定「谁排在前面」**。组顺序由规则在数组中的位置决定。
  典型用法：让「训练中·安全夹脱落」先于「训练前·系上安全夹」被识别，但组顺序仍然后者在前。
- **R6 的每一层都是「可选且可叠加」**，且只在同一测试点内生效，绝不跨测试点排序。

## 5. 排序键（与实现一致）

```
key = (
    partition_idx,                     # L0
    stage_idx,                         # 阶段（stages）
    (module_idx, module_subkey),       # L1/L2 模块（含前缀匹配的完整路径）
    top_idx,                           # L1 端（仅 top_module_mode=sub/group）
    testpoint_idx,                     # L3 测试点（未命中=承接值）
    type_idx,                          # L4-a 仅 sort_by_type 时非 0
    priority_idx,                      # L4-b 仅 sort_by_priority 时非 0
    explicit_seq,                      # 显式序号列（自然序）
    original_row_index                 # 稳定兜底，保证幂等
)
```

> 键的末位永远是原始行号 —— 这保证同一份输入**反复排序结果完全一致**（幂等），也保证「已排好的部分不会被打乱」。

| 能力 | 说明 |

| ✅ 多格式输入 | `.xlsx` / `.xlsm` / `.json` / `.csv`，自动识别 |
| ✅ 多 Sheet 批处理 | `--all-sheets` 一次排序全部工作表并统一写回 |
| ✅ 列自动探测 | 标题/顶级模块/功能模块/分类/类型/优先级/序号，支持参数覆盖 |
| ✅ 五层排序 | 分区 → 阶段 → 模块 → 测试点 → 组内次序 |
| ✅ 保留格式 | 值 + 样式 + 行高 + 超链接 + 批注 + 冻结窗格 + 列宽 |

## 7. 输入约定

### 7.1 必需列

| 角色 | 必需 | 说明 |
|------|------|------|
| 用例标题 | **是** | 用于测试点关键字匹配；缺失即报错退出 |
| 功能模块 | 否 | 缺失则回退到「顶级功能模块」，再回退到标题 `【版本】【平台】【模块】` 第 3 个括号 |
| 顶级功能模块 | 否 | 缺失则 `top_module_mode` 自动降为无效（全部同组） |
| 分类/设备型号 | 否 | 缺失则不分分区（全表单一分区） |
| 测试类型 | 否 | 仅 `sort_by_type` 时需要 |
| 测试优先级 | 否 | 仅 `sort_by_priority` 时需要；支持 `P0`~`P4` 及自定义序 |
| 序号列 | 否 | 存在则在组内优先使用（自然序，`启动-001` 会按 1 排序） |

### 7.2 列探测规则

先用**精确列名**匹配（`测试用例标题`、`顶级功能模块`、`功能模块`、`测试类型`、`测试优先级`、`设备型号`），
再退化到关键字包含匹配。精确优先是为了避免 `APP版本类型`、`移动端类型` 被误判成测试类型。

### 7.3 数据要求

- 首行为表头；**全空行自动跳过**（不参与排序、不写入）。
- 同一列内允许空值：空模块 → 走 R2 兜底；空分类 → 取 `partition.default`；空优先级 → 排该维度末尾。
- 标题可重复（同类用例不同版本），不影响排序，仅按原始顺序稳定排列。

## 8. 输出约定

| 项 | 默认 | 可配置 |
|----|------|--------|
| 输出路径 | `原名_sorted.xlsx` | `--output`；`--inplace` 覆盖原文件（自动 `原名.bak.xlsx`） |
| 工作表 | 仅当前活动表 | `--sheet 名称`；`--all-sheets` 全部 |
| 序号列 | 不追加（保持原列结构） | `--add-seq "执行序号"` |
| 报告 | 不生成 | `--report x.md`（分类→阶段→模块→测试点树 + 自检结论） |
| 未归类清单 | 不生成 | `--dump-unclassified x.txt`（`模块<TAB>标题`） |

**格式承诺**：除行顺序外，单元格值、字体/填充/边框/对齐、行高、超链接、批注、冻结窗格、列宽、
非目标工作表的全部内容均保持不变。`None` 与空字符串在一致性校验中等价（openpyxl 无法保留空串类型）。

## 9. 边界与异常场景处理

| 场景 | 行为 | 是否告警 |
|------|------|----------|
| 缺标题列 | 直接退出并打印现有列 | ❌ 阻塞 |
| 全空表 / 无有效行 | 跳过该 sheet，提示「未读取到用例行」 | ✅ 提示 |
| 模块未在 `module_sequence` 中 | 排到模块维度末尾，按模块名字典序 | ✅ 报告标注 |
| 模块无 `testpoint_rules` 且未声明 `keep_order` | 静默退化为「0 默认」单组（= 整模块保序），并**显式告警** | ✅ 强告警 |
| 规则全部未命中 | 承接上一个测试点（保序）；若模块声明 `fallback="tail"` 则落模块末尾 | ✅ 计入未归类 |
| 非法正则（如 `(` 未转义） | 自动退化为子串匹配，不中断 | ❌ 静默降级 |
| 模块被打散（同分区内出现两段） | 报告标注「N 处模块被打散」 | ✅ 告警 |
| 合并单元格 | 不做行搬迁保护，报告提示需人工确认 | ✅ 提示 |
| 超链接/批注 | 随行一起搬迁（只搬值会导致「链接粘错行」） | ❌ |
| 空标题行 | 保留原值置模块末尾（可用 `match:["^$"]` 显式归组） | ✅ 计数 |
| 输出文件被占用/只读 | 抛 `PermissionError`，不破坏源文件 | ❌ 阻塞 |
| 工作表名重复/超 31 字符 | 沿用原名，不重命名 | ❌ |

## 10. 使用说明

```bash
# 1) 最简：用内置默认流程
python sort_test_cases.py cases.xlsx

# 2) 指定配置 + 出报告
python sort_test_cases.py cases.xlsx --flow-config flow.json --report 排序报告.md

# 3) 先演练：只看结构，不写文件；顺带导出待补清单
python sort_test_cases.py cases.xlsx --flow-config flow.json --dry-run --dump-unclassified u.txt

# 4) 多 Sheet 批量（一次写回，保留全部工作表）
python sort_test_cases.py cases.xlsx --flow-config flow.json --all-sheets -o out.xlsx

# 5) 覆盖原文件（自动备份）+ 追加执行序号列
python sort_test_cases.py cases.xlsx --flow-config flow.json --inplace --add-seq 执行序号

# 6) 列名不规范时显式指定
python sort_test_cases.py cases.xlsx --module-col 功能模块 --type-col 测试类型 \
    --priority-col 测试优先级 --partition-col 设备型号 --top-col 顶级功能模块
```

**推荐工作流（三步收敛）**

1. `--dry-run --dump-unclassified` → 看未归类与缺规则模块；
2. 按清单补 `match` 关键词，或给该模块加 `keep_order` 声明（承认「只分组、组内保序」）；
3. 再跑，直到「未归类 0、无告警」→ 再 `--inplace` 落盘。

## 11. flow_config 结构（v2.2）

```json
{
  "partition": { "column": "设备型号", "order": ["公共", "BB2", "BB3"], "default": "公共" },

  "top_module_sequence": ["APP", "嵌入式固件", "联调功能", "系统后台"],
  "top_module_mode": "sub",

  "priority_order": ["P0", "P1", "P2", "P3", "P4"],
  "sort_by_priority": false,

  "stages": [
    { "name": "S1 APP 账号与准入", "modules": ["APP-启动", "APP-登录", "APP-手机号"] }
  ],
  "module_sequence": ["APP-启动", "APP-登录", "APP-手机号"],

  "module_options": {
    "APP-启动":  { "keep_order": true },
    "APP-验证码": { "fallback": "tail" }
  },

  "testpoint_rules": {
    "APP-登录": [
      { "group": "01 一键登录界面与入口", "match": ["一键登录界面", "进入一键登录"] },
      { "group": "02 密码登录与校验", "exclude": ["邮箱"], "match": ["密码登录", "密码位数"] }
    ]
  }
}
```

| 字段 | 取值 | 作用 |
|------|------|------|
| `partition.column/order/default` | 列名 / 数组 / 字符串 | L0 分区；空值取 default，未列出的值排末尾 |
| `top_module_sequence` | 数组 | L1 端顺序 |
| `top_module_mode` | `sub`(默认) / `group` / `weak` | 端在模块内聚块 / 端提到模块前 / 端不参与排序 |
| `priority_order` | 数组（如 P0..P4） | 优先级层次序；未列出的值排末尾 |
| `sort_by_priority` | bool（默认 false） | 全局开启优先级层；也可按规则用 `sort_by_priority` 单独开 |
| `stages[].modules` | 数组 | 阶段归属；未登记的模块排在最后 |
| `module_sequence` | 数组 | 模块先后，支持 `/ - _ · 空格` 层级前缀匹配 |
| `module_options.<模块>.keep_order` | bool | 声明「本模块只分组、组内保序」，不视为缺规则 |
| `module_options.<模块>.fallback` | `nearest`(默认) / `tail` | 未命中规则时：承接上一个测试点 / 排模块末尾 |
| `testpoint_rules.<模块>` | 数组 | **数组下标即组顺序** |
| `rule.group` | 字符串 | 测试点名（建议两位序号前缀） |
| `rule.match` / `rule.exclude` | 正则或子串数组 | 命中任一即归组 / 命中任一即跳过本规则 |
| `rule.priority` | 整数（默认 100，小者先判） | 只影响匹配顺序，不影响组顺序 |
| `rule.sort_by_type` / `rule.sort_by_priority` | bool | 该组内启用类型序 / 优先级序 |
| `type_order` | 数组 | 类型次序表，缺省内置 22 类 |

## 12. 规则编写规范（踩过的坑）

1. **先具体后宽泛**：`{match:["暂停"]}` 会吃掉「训练暂停超过30分钟恢复」→ 加 `exclude:["30分钟"]`。
2. **`exclude` 优于拆关键词**：`{match:["WiFi"], exclude:["蓝牙"]}` 比写十个精确词更好维护。
3. **同义写法要收全**：`第三方解绑` vs `第三方账号解绑`；`开始登录按钮` vs `"开始登录"按钮`（带引号）。
   宁可写更短的公共片段。
4. **模块一个都不能漏**：配置里没有 `testpoint_rules` 的模块会退化成单组；v3.0 起会强告警，
   若确实只想分组，请显式写 `keep_order: true`。
5. **长流程模块靠保序**：引导/校准这类 300+ 条按 PRD 顺序写好的模块，只需覆盖段落关键词，
   其余交给默认 `nearest` 兜底，不要强行按类型打散。
6. **跨端同名模块用 `top_module_mode=sub`**：`设备状态与设置` 在 APP/固件/联调三端都有，
   不按端聚块会出现「APP→固件→联调」反复横跳。
7. **空标题行**：`{ "group": "99 空行", "match": ["^$"] }` 放最后，避免污染未归类统计。

## 13. 质量门禁（交付前必过）

| 检查 | 判定 | 方式 |
|------|------|------|
| 内容零改动 | 排序前后行内容多重集完全一致 | 自动 |
| 条数一致 | 输出行数 = 输入行数（逐 sheet） | 自动 |
| 模块成块 | 同一分区内同一模块不出现两段 | 自动 |
| 未归类 | 0 条（`nearest` 承接的不计） | 自动 + dump |
| 规则覆盖 | 每个出现的模块都有规则或 `keep_order` | 自动告警 |
| 格式保真 | 值/样式/行高/超链接/批注/冻结窗格 | 代码内搬迁 + 抽样核验 |
| 抽样可读 | 每组首条是「进入/展示」，末条是「异常/性能」 | 人工 |

## 14. 设计原则

- **业务链路优先**：排序反映真实使用顺序与前置依赖，不是任何形式的字典序。
- **保序优于重排**：规则只负责「把该聚的聚起来」，不负责「把原本有序的打乱」。
- **属性不越权**：类型、优先级、状态默认只是标签。
- **内容与格式零改动**：只动行号。
- **可配置可扩展**：流程与脚本解耦，换项目只换 JSON。
