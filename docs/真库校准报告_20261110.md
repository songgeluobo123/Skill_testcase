## 三、已修：3 个真缺陷（均已回归覆盖）

### 🔴 1. `read_only=True` 静默读到 0 行（最严重）

`coverage_audit.py` / `defect_audit.py`（×2）/ `input_readiness.py` 共 4 处用了 `load_workbook(read_only=True)`。
`read_only` 不读真实单元格，而是按文件内 **dimension 元数据**决定遍历范围；这份库被云端工具存过，元数据写成 `A1:A1`。

实测对比：

```
read_only=True  : dimension=A1:A1      非空行=1      ← 连表头都没读到
普通模式        : dimension=A1:O2412   非空行=2412   ← 真实数据
```

后果不是报错，是**静默读空**：输入就绪度判「0 分」、覆盖率全 0、缺陷审计空表——而报告看起来一切正常。

修法：新增 `scripts/xlsx_util.py`，一律走普通模式并显式 `kw.pop("read_only")` 挡掉。三处调用点全部改用它。

### 🟠 2. 字段整体缺失被当成「全部违规」

第 4 项（设计方法）/ 第 10 项（孤儿）在库里**根本没有对应列**时，逐条判违规 = 100% 失败。

修法：全部为空 → 整项跳过；部分填了 → 照常判「填错的那些」。跳过段在汇总里**单独列出**（「已跳过的闸门…不代表通过」），不静默。

反向也防：给了 `--requirement-rules` 就说明要做需求追溯，此时全库无 `coverage_rule` 是**真孤儿**，不许跳过。

### 🟡 3. 标题长度写死 20 字，无法配置

新增 `--title-max`（默认 20，可传 30）。实测差 77 条：20 字 → 92 条不合规，30 字 → 15 条。
