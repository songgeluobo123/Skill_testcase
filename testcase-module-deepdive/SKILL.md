# 测试用例模块穿透深挖

## Overview

以「单模块」为单位，对测试用例库做一次穿透式体检并安全落地优化。核心是**两级分批**：

- **批次A（低风险）**＝补缺口用例 + 硬化弱预期。只增不删，可随时回滚。
- **批次B（高风险）**＝删真重复 / 合并 / 改名消歧。**必须单独确认**，逐条给证据链。

每批都走同一条链路：`dry-run 预览 → 用户确认 → --apply → 重排 → 门禁 → 回读核对`。

## When to use

- 用户要求对某功能模块做「深挖 / 穿透体检 / 补用例 / 去重 / 硬化弱预期」。
- 用户以「线③」「批次A」「批次B」「换个模块继续」等措辞推进用例库优化。
- 需要在**不破坏既有覆盖**的前提下，批量精简或补强某模块。
- 不适用：全库级别的初版生成（用 testcase-generator）；纯排序（用 test-case-sorter）。

## 前置：模块级标准动作

1. **导出全量**：`dump_module_<模块>.py` → 打印 优先级/测试类型/设备型号分布 + 弱预期扫描 + 全量明细（按编号排序）。
2. **审计四看**：① 场景/质量属性缺口；② 弱预期（空壳断言：仅"进入页面/查看X""符合要求""无异常"）；③ 冗余（真重复 vs 合法变体）；④ 错标/stale（类型错标、备注「暂无法触发」等）。

## 批次A：补 + 硬化（低风险，先做）

- **补缺口**：按 异常/边界/安全/兼容/国际化/性能 等属性补，**默认全部落「公共」**（跨端同质逻辑）。
- **🚨 专项缺口补缺（模块专项数=0 或严重偏斜时必查）**：三分类里只要模块**有界面/有操控**，就必然有"仅横屏/仅竖屏"的**布局差异面**与**操控方式差异面**，二者都应有专项承载。审计时先看分布：**某端专项 = 0 而另一端 > 0 → 大概率漏了镜像专项**（如 设备端-休眠 原为 公共41/横屏专项2/**竖屏专项0**，横屏有"触屏滑动手势"却无竖屏"遥控按键"镜像）。补法：镜像该端同族用例（横屏"触屏滑动手势仅退出"↔ 竖屏"遥控按键仅退出"）+ 补该端布局/字号专项。**注意**：布局/操控专项落 `竖屏专项`（APP=国内版本,国外版本、环境=大屏端）或 `横屏专项`（APP=横屏触摸版、环境=跑步机横屏设备）；**标题必带判别关键词**；**竖屏专项正文禁"滑动/触屏/点击屏幕"**（见坑14）。
- **硬化弱预期**：挑 P0/P1 里最关键的 **5~7 条**，把「进入页面」类空壳改成**可判定断言**（字段清单+数值一致+单位+跨端一致+无溢出）。
- **🚨 症状化预期（高危病种，优先处理）**：预期写的是"当前缺陷/现状"而非"期望结果"——如 `无密码复杂度校验`、`不兼容大小写`、`新旧密码可以保持一致`、`未做该限制`。这类预期**无法判定对错**（开发照做即通过、改好反而失败）。处理法：
  1. 改写为**条件式可判定断言**（「若产品规则 A 则…；若规则 B 则…」）；
  2. 把"当前版本现状"写入**备注**并注明回归条件（如「当前版本未做 X，上线后回归第 1 条」）。
  检测线索：预期含「无/不做/不兼容/未」等否定词且描述的是能力缺失，或备注写着"未做/暂不支持"而预期却是期望行为（**二者矛盾**）。
- **🚨 语义错位预期（高危病种）**：预期与**标题/步骤/前置**不匹配或自相矛盾，多为复制粘贴残留。两型：
  1. **预期错位**：预期内容与标题讲的不是一回事（如标题「一次澄清双指向／观察澄清展示与次数」，预期却写成「简述今日训练计划」——疑似抄自别的用例）。
  2. **前置-预期矛盾**：前置设定的状态与预期结论相反（如前置「基础产品返回**无继续权限**」，预期却写「**可继续**今天的训练计划」）。
  处理：**修正预期使其与标题·步骤·前置对齐**（不是硬化，是纠错）。检测线索：预期与前置含相反的肯定/否定词；预期单一薄句与标题的多要素描述量级明显不符。
- **🩹 空壳预期成簇（复制粘贴式）**：多条不同状态/分支的用例**预期完全相同**（如 4 条不同状态页 UI 展示预期都是「弹出今日训练内容卡片／卡片内容正确」）。这类"看起来不空"实则**无区分度**。处理：**按各状态差异化补具体字段**（课程名/时长/状态标签/按钮文案），使每条各自可判定。机械扫描线索：**正文近重复 J 高**但标题分属不同状态。
- 规模参考：补 ~10-12 条 + 改 ~5-7 条。**若模块呈"两代质量"**（早期批次断言极薄如"注册成功/提示格式错误/成功拉起授权页"，后期批次已含 mock/阈值/链路）或**症状化预期/空壳 P0 密集**，则**硬化为主**——可扩到 20 条以上，优先覆盖 P0。
- 📉 **"预期系统性偏短"模块（整模块级病）**：弱词/过短命中率 **>50%** 时，说明整模块预期普遍只有 ~20 字（如 `按钮宽度自适应 / 文本换行不溢出`）。**硬化要按簇批量做**，不是挑 5-7 条：先识别同形态簇（如「X 界面翻译覆盖」6 条、「格式本地化」4 条），**每簇用统一硬化模板**补齐「具体界面元素清单 + 无 key 裸露/无原语言残留 + 具体格式化数值 + 跨界面一致」。典型：设备端-国际化 56/108 偏短 → 硬化 12 条。
- 新增行的 **编号/标签/流程三列留空**，交重排脚本回填。
- 补缺前**必须全表跨模块核验**（用关键词扫**全表**而非仅本模块，输出「模块内命中数 / 全表命中数」两列）：确认该缺口**全表**都不存在，或已存在但属**其他模块视角**（如「音量/语速/静音」由个人中心覆盖 UI 设置 → 语音模块应补「设置实时作用于播报」的联动视角，而非再写一遍设置 UI）。只扫本模块会把"已被别的模块覆盖"误判成缺口。
- **按「层」找空窗**（高价值审计手法）——高度专业化的模块常只覆盖核心逻辑层，系统性遗漏**输出/呈现/外设层**。例：设备端-语音只覆盖「播报**调度**逻辑」（去重/合并/优先级/打断/冷却/限频/离线降级），而「**音频输出路由层**」（混音 ducking / 蓝牙耳机切换 / 音频焦点抢占 / 扬声器外设 / 息屏锁屏 / 解码失败）全表 0 覆盖。审计清单：核心逻辑层 → 输出层 → 外设/兼容层 → 异常兜底层 → 国际化层。
  - **对话型模块（AI 助手/语音 Agent）的专用分层清单**：业务逻辑层（白名单/状态机/意图）→ **交互层**（barge-in 打断播报、远场/非正对识别、误触发防护）→ **隐私安全层**（麦克风/摄像头采集数据的本地留存与传输加密）→ **内容安全层**（敏感词/违规/医疗诊断/不作为承诺）→ **会话管理层**（上下文长度上限/主动清空/会话超时回收）→ **可信层**（埋点上报、无障碍）。典型：设备端-AI教练 92 条覆盖了状态机/白名单/弹窗，但上述五层全 0。
  - **⚠️ 同词不同层，勿误判已覆盖**：同一关键词在不同模块属**不同层**——「打断」在语音模块=**播报调度**层（P0/P1 抢占），在对话模块=**对话 barge-in** 层（用户说话打断 TTS）；「音量」在个人中心=UI 设置层，在语音模块=播报实时生效层。扫全表命中该词 ≠ 本模块视角已覆盖，须**回到层的语义**判断。

## 批次B：删 / 并 / 改名 / 类型修正 / 优先级修正 / 笔误修正（高风险，后做，必须确认）

**真重复 vs 合法变体——判定铁律：**
- ✅ **真重复**：同触发 + 同对象 + 断言被子集完全覆盖 → 删薄的那个（先确认无独有断言）。常见形态：同一动作的两个入口（一个含 stale/不存在的入口名）、同一字段的"数据"版与"展示"版、被硬化后的厚版覆盖的弱壳版、**同一动作「两种命名世代」**（正式长标题`"X"界面点击返回按钮能返回Y界面` vs 口语短标题`X点击返回Y`——后者常是早期用例、断言更全，前者后加却更薄且类型错标）。
- ❌ **合法变体保留**：左右镜像（日期左/右切换）、维度（日/周/月/年）、模块（热身/放松/主训练）、**功能×UI 分解**（"X选择" vs "X选项展示"）、公共×专项（同功能不同设备类）、**竖屏专项×横屏专项对称**、**同动作不同前置态**（走完校准 vs 跳过校准）、**同动作不同返回目标**（四周→本周 vs 四周→首页）、**不同按钮/栏目**（重试 vs 联系支持、课程库 vs 训练记录）、**同名字段不同含义**（训练时长 vs 训练时间）、选项变体（慢/快速、简/繁体、开/关）、有·无 / 开始·继续 等状态变体。
- ⚠️ **弱预期/stale 不是重复**：按「占位符缺陷只能充实不能删」→ **保留+充实**（硬化预期 + 把失效备注换成构造说明，如"用接口 mock/桩构造"、"当前版本不支持，功能上线后验证"）。
- 📝 **备注三态修正（thin / stale / 矛盾）**——备注列常有三类病，须分别处理：
  1. **thin（词组式缺标注）**：备注仅有词组（如 `RTL`/`格式边界`/`切换韧性`/`回退边界`/`并发韧性`/`离线韧性`）而无「设计方法/维度/界面」标注 → 补齐为 `设计方法:XX | 维度:XX` 格式。**只补已有体系里的标注，不新造规则 ID（如 R-xxx）**，避免臆断需求链。
  2. **stale（场景失效）**：备注写「无该场景/无触发场景/暂无法触发/当前版本不做」→ 换成**构造说明**（如「用接口 mock/桩构造失败态」）并注明回归条件。
  3. **矛盾（与预期冲突）**：备注与预期结论相反（如预期「返回进入前的页面」，备注却写「没有，界面保持在AI界面」）→ **以产品现状为准改正备注**，并同步核对预期是否需一并修正。
- 🔧 **类型错标修正**：标题/预期为纯展示布局类（含"UI/布局/展示/选中态"）却标为功能测试 → 改 **UI测试**（口径"展示→UI测试"）。但 i18n/兼容/性能效率/边界 即便标题含"展示"也**不改**（类型本身正确）。只改 unambiguous 的。
- ⚖️ **优先级提级补位**：删掉某薄副本、保留其厚副本后，若该路径为核心功能（返回/跳转/登录锁定等主流程）或原薄副本是 P0 → 把保留项**提级**（如 P1→P0 / P2→P1）以维持覆盖等级；与同类用例优先级口径对齐。示例：删掉「密码连续输错锁定防护(P0)」+「手机号登录连续输错密码锁定(P0)」两薄副本后，把保留的「暴力破解限制(P1，超集)」提为 P0。
- ✏️ **笔误修正**：前置/步骤里的明显笔误（如"今日**进化**生成异常"应为"今日**计划**生成异常"、"账号**有无**训练计划安排的日期"应为"当前日期**无**训练计划安排"）→ 顺手修正，保证可执行性。用子串替换（含新词且旧词完全消失）作 verify 判据。
- 🧹 **乱码/误替换残留修正**（高危数据病）：曾发生全局「App→设备端 / Apple→设备端le」式误替换，会把 `Apple` 变成 `设备端le`、`App Store` 变成 `设备端 Store` 等。发现可疑乱码（中英混排如"设备端le""贯标"）→ 先**全表扫该词**定位范围，再按语义还原（`设备端le`→`Apple`、`贯标`→`光标`）。verify 加「全模块残留扫描=0」。**误报陷阱**：`设备端App进程`（设备端模块里描述"杀掉设备端 App"）是**合法**写法，非误替换，勿改——正则扫 `设备端[A-Za-z]` 时须逐条按语义判别。
- 🗂️ **列口径统一**：模块内枚举列（如「测试环境（I列）」「APP版本类型（H列）」）常因多批次新增而混入异值。**以模块主体值为准**归一，逐条列出旧值→新值。**主体值因模块类型而异**：移动端两模块（注册/登录）主体=**Android/iOS**（异值「大屏端」「移动端」须归一）；设备端各模块主体=**大屏端**（公共→大屏端、横屏专项→跑步机横屏设备）。改前先统计模块主体分布确认。
- 📌 **前置补构造说明**：前置为空（或只有"已进入X界面"）的用例缺**可复现的构造条件**，尤其依赖异常/边界态时（如"计划生成失败态""导航失败"）→ 补「构造方法」（接口 mock/桩、清空数据、断网、杀进程等）。属低风险补齐，可与批次A/B 任一并行。
- 🏷️ **改名消歧**：标题混淆但用途不同（如 i18n 版与普通版同名、错别字前缀、短信/邮件通道同义标题）→ 改名，不删。
- 🅰️ **专项关键词合规（纯改名、零风险）**：`设备型号=横屏专项` 的标题**须含「横屏」或「触屏」**，`竖屏专项` **须含「竖屏」或「遥控」**。模块内常有一批专项条目标题**完全无判别关键词**（正文含"横屏布局/竖屏布局"但标题漏了）→ 逐条补关键词（多数加在词首最自然，如`横屏课程库双栏布局展示`），**分类正确则无需动设备型号**。**判定口径唯一权威 = 「含」关键词**：主表主流形态是**关键词嵌入**（如"校准中遥控跑带启动键无效"、"WiFi屏幕键盘横屏布局展示"），**前缀只是子集**；**勿用 startswith**（会多判 +21/+25 条）。另注意该列是**设备型号（D 列）**，**不是功能模块（C 列）**。改名后由门禁校验无标题冲突。典型：设备端-登录批B 补 13 条、训练课程库批B 补 21 条（含把"横屏/竖屏"放词首）。
  - **🌐 全表批量补关键词（独立工程，模块全部收口后统一做）**：脚本 `scan_all_kw_gaps.py`（扫描+候选改名+冲突检测）→ `apply_all_kw_rename.py`（dry-run/apply，备 `_before_all_kw_rename.xlsx`）→ `verify_all_kw_rename.py`。**命名策略**：关键词置于标题最前；**横屏专项**含 `滑动/触屏/点击/手势/触摸/长按/双指/拖拽` 用**触屏**、否则**横屏**；**竖屏专项**含 `遥控/焦点/按键/方向键/确认键/返回键/导航键` 用**遥控**、否则**竖屏**。**特例**：`AI教练-` 开头标题保留模块前缀，关键词插其后（`AI教练-横屏欢迎页背景渐变`）。**落库前必做两项检测**：① 新标题与全表既有标题是否冲突；② 批内是否产生重复新标题——任一非 0 即 ABORT。典型：2026-09-19 一次补 112 条（首页34/个人中心30/引导19/训练12/训练记录10/AI教练7），缺口 117 → 0，零冲突。
- 🧾 **标题冗余分类标签清理（批量改名，需用户确认）**：部分模块的标题里嵌了**分类标签**（如 `XX-公共-...` / `XX-触屏-...`），而"设备型号"列已完成分类 → 属冗余噪声。做法：先全表扫该标签确认**仅本模块独有**（如全表 `-公共-` 仅 21 处、全在本模块），再批量剥离标签主体（`自由跑-公共-训练中页速度调节` → `自由跑训练中页速度调节`）。**红线**：`横屏专项` 标题里的 `-触屏-`/`-横屏-` **不可剥离**——它们兼作专项关键词，剥离即触发关键词缺口。所以**只剥「公共」标签，保留专项标签**。因改 20+ 条标题，**必须让用户在批次B 确认时单独拍板**（选项：全落 / 保留标签只做其他 / 看逐条明细）。

**推荐先跑模块内扫描**（一个脚本可多合一）：① 标题 2-gram J≥0.72 + 正文 3-gram J≥0.80 近重复对；② 类型错标启发式（标题含 UI 特征但类型非 UI）；③ 备注三态（stale 含"暂无法/不做/待确认/不合理/暂无/无该场景/无触发"；thin ≤6 字词组且非"设计方法/测试方法/去功能化/覆盖"开头；矛盾须人工比对预期）；④ 枚举列异值行（环境/APP 等）；⑤ **前置为空行**（缺构造说明，批B 补）；⑥ **预期过短行**（<25 字）**或编号残缺行**（预期以 `2./3./4.` 开头 = 缺第 1 条，多因"去功能化合并"只留后半截）；⑦ **专项关键词合规**（读**设备型号 D 列**，用「含」关键词口径，批B 改名补关键词+全表余量统计）；⑧ **全列笔误扫描**（清楚筛选/登陆/… 并打印命中列）。再逐组人工判定。
- **机械扫描 0 命中 ≠ 无真重复**：标题高度分化的模块（如移动端-注册，标题各异但语义重复）Jaccard 会全 0。此时必须**按语义人工梳理近亲簇**（同一触发/对象的不同措辞，如"手机号已被注册" vs "已注册手机号再次注册提示"、"勾选协议后允许注册" vs "未勾选协议不可注册"），再逐条比对断言是否被覆盖。
- **两代混合模块的"跨代真重复"**：模块常同时含「生成器版（备注带 `覆盖规则=R-xxx；测试点=TP-xxx`）」与「维度版（备注带 `维度=DX；界面=X；源编号=TC-UI18N-xxx`）」，二者会**对同一测试各写一条**（如 12 小时制、不支持语种回退）。这类对**标题 Jaccard 低**（措辞不同）机械扫描常漏，须人工按「同触发 + 同对象 + 同预期」逐对核实。
  - **取舍规则**：优先**保留 R/TP 溯源版**（保需求可追溯性），删 D 维度重复版——前提是**该维度在模块内还有其他成员承载**（删前逐一确认，如 D2 缺失回退仍有 D2 其他条）。若 D 版覆盖范围更广（界面=全局）而 R 版仅单页，则反过来保留 D 版。
- **正文近重复扫描很关键**：它能抓到标题完全不同、但正文（前置+步骤+预期）几乎相同的真重复对（命名世代差异型），单看标题会漏。

**关键坑（扫描误报）**：
- **竖/横屏专项对称对会报 J=1.00**——因分词时抹掉了"竖屏/横屏"前缀。识别为合法，勿删。
- **类型错标启发式大面积误报**——国际化/兼容性/性能效率/边界测试的标题常含"展示/布局"，但其类型正确。只对"纯 UI 但标功能测试"出手。

## 标准执行链（每批）

```
1. 写 scripts/apply_<module>_<batch>.py（含 --dry-run / --apply；--apply 前先 os.remove+save 备份 _before_*.xlsx）
2. dry-run 输出计划 → 用 AskUserQuestion 让用户确认（选项文案"确认落库/确认执行删并"）
3. --apply
4. 跑 organize 脚本（重排 + 重算编号/标签/流程 + 刷新整理 sheet）
5. 跑 final_check 门禁（标题重复=0 / 占位符=0 / 红线=0 + 打印总数与分布）
6. 写 scripts/verify_<module>_<batch>.py 回读核对（补N/N + 改N/N + 删N消失 + 改名生效 + 类型/优先级修正 + 笔误用「含新词且旧词完全消失」判据）
7. 追加当日 memory 日志 + 更新项目 MEMORY.md 终态与轮次索引
```

## 关键坑位（务必遵守）

1. **编号跨重排漂移**：归类编号会被重排脚本重算，**跨重排一律按标题定位**，编号仅作溯源。
2. **新增行 P/Q/R 留空**，否则重排不生效。
3. **删除用倒序 `delete_rows`**，避免行位移错删。
4. **verify 子串误报**：若"替换文案里回引旧文案"（新备注含旧词），判据必须用**旧值精确相等**而非子串，否则误报未替换。
5. **同名标题跨模块冲突**会在门禁触发"标题重复"→ 加模块前缀消歧并同步改生成脚本。
6. **批量改动统一先 dry-run**，给证据链，用户确认后再 --apply，原文件备份 `_before_*.xlsx`。
7. **误替换类乱码修正后，须另跑一次「全表残留扫描」**（不止本模块）——该类错误常横跨多个模块。扫后用语义判别合法巧合（如 `设备端App进程`）与真残留，把结论写进 memory（如「全表核查已完成收口」）以免重复劳动。
8. **新建 verify 脚本前先确认文件名未被占用**：`scripts/verify_<module>_merge.py` 可能已被**同名的历史遗留脚本**占用（如一份与当前工作流无关的「横屏专项 JSON 对拍」脚本），直接 Write 会被拒（"File has not been read yet"）。改用 `<module>_mergeb.py` 等变体名，并在 memory 记录该遗留脚本以便后续清理。
9. **核对脚本的列号必须与主表列位一致**：`设备型号=横屏专项/竖屏专项` 在 **D 列（索引 3）**，**功能模块（如"设备端-登录"）在 C 列（索引 2）**，二者极易写反。写反的后果是**静默恒真/恒假**（如合规判定恒报 0 缺口，误以为全合规）。凡涉及枚举值比对，**先用 `dump` 打印一行确认列位**，再写判定。
10. **专项关键词缺口口径固定为「含关键词」，禁用 startswith**：主表主流是**关键词嵌入**形态，前缀只是子集。同一数据用不同口径会得出 138 / 152 / 184 三个不同总数。**报告、扫描、verify 一律用 `'横屏' in t or '触屏' in t`（竖屏同理）**，并在脚本注释写死口径，防后人"修正"错方向。
11. **笔误必须逐列定位命中列再改**：同一笔误可能出现在**步骤 K 列**而非预期 L 列（或前置 J 列）。若只扫/只改 L 列 → 残留。做法：扫描时**全列命中**并打印命中列号，修正时按命中列替换；修完 verify 扫全列残留=0。
12. **批B 含改名时，verify 对已改名条目一律用新标题查表**：若 verify 仍按**旧标题**（改名前）查找 → 误报"缺失/未达标"。规律：`verify 的标题列表 = RENAME 的 new 值 ∪ 未改名条目的原标题`。同理，`apply` 脚本内若同一行既 RENUM 又 TYPO，注意**执行顺序**会让后一步的前置判据失效（本例 RENUM 先改写了预期，导致 TYPO 的"旧词存在"判据在 apply 阶段失效——虽结果正确但判据失真）：行内多操作时，**按「同列动作合并」或显式重读单元格**。
13. **apply 脚本默认「不带参即落库」（非 dry-run），重复 apply 会静默重复落库**：标准模板 `dry = "--dry-run" in sys.argv`，**只在显式传 `--dry-run` 时才预览**。若误判"此前只跑过 dry-run"而再执行一次 `python apply_x.py` → 追加型动作（ADD）**重复插入**，而 FIX 型（改预期）因幂等无感，导致只有 ADD 出现重复。典型症状：主表 +N 行、门禁报「标题重复 N 组」，且重复的恰好是 ADD 清单标题。**恢复**：`_before_<module>_<batch>.xlsx` 是**上一次 apply 前的快照**，`shutil.copyfile(backup, SRC)` 覆盖主表即回到正确态，无需手工删行。**铁律**：落库链 `apply(--apply) → organize → final_check → verify` **一次跑完，全程不重复 apply**；任何"复跑"前必先带 `--dry-run` 确认它真的只预览。**推论**：verify 若发现"补 N 条"全部命中但条数是 2N，先怀疑重复落库。
14. **门禁红线是「正文级」且含「滑动」——新增竖屏专项用例必须自检措辞**：门禁对 `竖屏专项` 校验 **title+步骤+预期**（不止标题）是否含 `触屏` / `滑动` / `点击屏幕`；对 `横屏专项` 校验 `遥控`。**哪怕是"滑动手势无效"这类负向用例也不能出现"滑动/触屏/点击屏幕"字样**（本次 休眠-055 因标题+步骤含"滑动"被拦下）。**写法**：改用「非遥控输入」「触摸/手势操作」——"手势"可用，"滑动/触屏/点击屏幕"禁用。**流程**：批次A 落库后**先看门禁红线**再 verify；命中则用定点 patch 脚本改写该行标题+前置+步骤+预期 → 再 organize → 再门禁。
15. **「显示」不是可靠的 UI 类型信号**：全表标题含"显示"的类型分布 = 功能11 / UI15 / 国际化13（混用）→ **勿把"…显示"一律改 UI 测试**。只改 unambiguous 的（如"…完整展示"对齐模块内既有 UI 同族）。同族一致性优先：若模块内"覆盖/层级类"全是 功能测试，新增/修正的同族也保持 功能测试。
16. **新增用例的类型/列口径必须与既有同族对齐，并抽查列口径**：新增前先 dump 同族用例的类型；落库后抽查"型号=公共 却带 横屏触摸版/跑步机横屏设备（或反向）"这类列口径不一致行，批B 归一。
17. **预期中藏 `\xa0`（不换行空格）**：早期用例常用 `\xa0\xa0\xa0` 当"假缩进/排版填充"（启动模块 003/011/016 分别 9/12/9 处）→ 渲染不可控、破坏文本比对、导出后显示异常。**硬化时整体重写预期即顺手清除**；建议加独立检查 `'\xa0' in 预期`，并把命中数打印出来（`apply` 的 dry-run 里已带 `(含\xa0 N)` 统计）。
18. **模块 0 专项 ≠ 缺口——先看"对称性"**：判据是"**一端专项 > 0 而另一端 = 0**"的不对称，而非"专项总数少"。若模块用「双通道公共」（标题/前置标注横竖两套 + 预期含「跨竖屏/横屏表现一致」+ 竖屏端子段）承载了布局差异，则两端对称的 0/0 **无需强补专项**（典型：设备端-启动 25 条全公共，004/013/017 双通道已覆盖）。反之不对称必补镜像专项（典型：设备端-休眠 横屏专项2 / 竖屏专项0 → 补竖屏专项 3）。
19. **模块穿透收尾自检（每条线③批B 后必跑）**：`scan_<mod>_pairs.py` 复扫 4 项应全 0 —— 标题近重复(除合法变体) / 备注三态 / 前置为空 / 预期过短或编号残缺；再跑 `final_check.py` 看 标题重复/占位符/红线。全 0 才宣告模块收口。
20. 🔴 **给主表加列后，整行搬运/重排脚本会静默错位（最隐蔽的一类事故）**：`organize_cases.py` 物理重排时曾写死 `range(1, 19)`，主表扩到 21 列后，新增的 S/T/U（19–21 列）**不跟随行移动**，留在原物理行 → 内容与标签错配（实测 S 功能点与模块不匹配 **642/2360**）。症状：抽查发现「语音模块普通播报用例被标 Deutsch」「自己刚落库的 Español 用例显示成别的语种」，且用关键词匹配反查**查不到命中词**（因为值根本不属于这一行）。**修法**：`LAST_COL = ws.max_column`，读写均用 `range(1, LAST_COL + 1)`；**善后**：写 `rebuild_stu.py` 这类「按行内容重算新增列」的幂等脚本重算一遍。**铁律：每跑一次 `organize_cases.py`，就跟跑一次重算脚本校验，正常应输出「差异 0」；差异非 0 即错位复发。** 通用教训：任何"整行读取→排序→写回"的脚本，列数必须动态取，禁止写死。
21. **语种/多语言类批量改写的四个必检点**（V1.0 多语言优化实证）：
    - **扫描必须覆盖 E 标题 / K 步骤 / L 预期 / N 测试数据 四列**：失效语种常以缩写（FR/CS/NL/IT）藏在 K 与 N 列，只扫标题会漏 15%（本次 90 条漏 15 条）。
    - **语种枚举串（`EN/DE/FR/IT/NL/CS`）替换必须无条件执行**：若只在 K 列检测到就设开关，那么只出现在 L 列的枚举串会被"逐个缩写替换"规则拆成 `EN/DE/ES/ES/ES/ES`，语义崩坏。
    - **示例词要建"四语种等价映射表"**：步骤/测试数据里的 `示例=Chargement…`、`Étape 1/5`、`« Erreur »` 等，只换语种名不换示例词，改完仍是失效语种内容。先扫全量 `示例=` 取值（通常 10 种量级），逐条人工定译。
    - **改写目标语种要按"终态缺口"配平**（QUOTA 轮询），否则自动分配会让 90 条里 33 条全灌同一语种，极差失控。配平后还应复核门禁是否产生**标题重名**（不同语种用例被改写成同一语种会撞名）→ 撞名多为**类内变体**（不同日期分隔符/不同格式），加限定后缀而非删除。
22. **删除类操作的关键词扫描必须逐条过目，警惕"泛词"误伤**：典型的 RTL 关键词组含「**双向**」，会命中「水平垂直双向居中」「双向绑定」等完全无关的合法用例（本次 9 条命中里 1 条是误命中）。另外「阿拉伯」也可能命中课程名/地名。**做法**：扫描出候选后先 dump 每条的模块+标题+步骤+预期+优先级，**人工确认每一条确实属于该无效场景**再写 DELETE 清单；脚本里同时维护一份 `KEEP_TITLES` 白名单做防御（`if t in KEEP_TITLES: continue`），并在文档里记录误命中原因，避免后人重扫时重复踩坑。

## 无删除场景

若审计发现模块近乎零冗余（仅个别疑似），**穿透复核后可「零删除」收口**——用检索/扫描脚本给出证据链证明疑似项为合法分支变体，不强行删。**判断依据**：机械扫描（标题 J≥0.72 / 正文 J≥0.80）命中的近重复组，若差异维度属合法变体（不同对象如调速vs调坡、不同配置如带值vs不带值、相反方向如上调vs下调、不同入口/触发、不同关注点），即判合法。
- **「零删除」批次B 不等于无事可做**：删除项为 0 时，批次B 仍可承载三类低风险收尾——① **前置补构造**（前置为空/仅"已进入X"的行补可复现构造，异常态注明 mock/桩）；② **剩余空壳硬化**（批A 漏网的 P0/P1 同族空壳）；③ **语义修正**（预期与标题/前置矛盾处纠错）。把这三类归入批次B 一次收口，模块即彻底闭环。示例：设备端-AI教练批次B = 零删除 + 前置补构造9 + 预期硬化6 + 语义修正1。
- 🧬 **模块质量分级（影响批次A/B 配比）**：由 `testcase-generator` 生成、带「覆盖规则 R-xxx + 测试点 TP-xxx」溯源的模块，**质量通常高**（阈值/测试数据/边界齐全，且常有既往合并记录如"合并原 XXX"）→ 批次A **以补缺口为主、硬化少**（~3-7 条）；批次B 常**零删除**。反之，手工早期批次往往"两代质量"，批次A 硬化为主（20+）。
- **既往合并痕迹**：备注含「合并原 XXX/YYY」的行 = 已被前人合并过，**勿再拆**；其薄预期（如"均展示正确"）仍需硬化。
