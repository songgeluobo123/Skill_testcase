# 优先级分级策略（P0 / P1 / P2 / P3）

本文件为 `testcase-generator` 提供 **P0–P3** 四级优先级口径，是优先级分级的**唯一权威来源**。全技能统一采用此四级——**不再使用 P1–P4 体系，无 P4**；生成用例时 `priority` 字段仅可取 `P0` / `P1` / `P2` / `P3`，不得出现 P4 或其它分级。

## 一、分级总览（三色区分）

| 级别 | 颜色 | 定义 | 执行要求 | 占比建议 |
|------|------|------|----------|----------|
| **P0** | 🔴 红 | 可行性/概念性测试：横屏版主流程功能（用户基本使用流程、横屏主界面与关键交互）；竖屏功能移植横屏后的等价可用性；各端联调测试 | 每次构建必跑，100% 通过方可发布（一票否决） | 10%~15% |
| **P1** | 🟠 橙 | 主流程必测：按主流程步骤逐步拆解的必须执行功能（依据横屏 UI 流程图编写用例）、等价类相关功能（含异常执行场景）、横屏布局与适配、AI 数据准确性、设备监控灵敏度、数据安全 | 每轮主测试必覆盖 | 25%~35% |
| **P2** | 🔵 蓝 | 显示完整性：横屏界面 UI 显示完整性，以及不影响主流程的基本功能（如横屏下控件不遮挡、不溢出） | 常规迭代覆盖，回归可选 | 35%~45% |
| **P3** | ⚪ 灰 | 美观与兼容：UI 显示正确性与整体布局美观（文字、Logo、图片、按钮、链接显示正确，旋转后布局正确）；横屏响应式、设备与系统版本兼容性（Android 与 iOS）；产品认证标准性能测试 | 全量或按需覆盖，不计入发布门禁 | 10%~20% |

## 二、五维评分模型（定量定级）

对每条候选用例，5 个维度各打 1~5 分，加权求和（满分 25）映射优先级：

| 维度 | 含义 | 5 分 | 1 分 |
|------|------|------|------|
| D1 业务重要性 | 横屏主路径 / 商业核心 | 主流程必经 | 边缘美化项 |
| D2 用户影响 | 失败的可感知与严重程度 | 主流程阻断/数据失真 | 仅观感瑕疵 |
| D3 故障概率 | 历史缺陷与改动频率 | 高频改动/重灾区 | 极稳定少变更 |
| D4 修复成本 | 暴露后修复与回滚难度 | 需发版/固件硬件 | UI 微调 |
| D5 使用频率 | 真实用户触发频次 | 每次必达 | 极少触发 |

加权建议：D1×1.2、D2×1.2、D3×1.0、D4×0.8、D5×0.8。

**风险总分 → 优先级**：≥20 → P0；14~19 → P1；8~13 → P2；<8 → P3。
**保底规则**：数据安全用例即便总分低也**保底 P1**；横屏主流程阻塞直接 **P0**。

## 三、硬规则决策表（命中即定级，高于评分）

| # | 规则 | 定级 |
|---|------|------|
| R1 | 横屏主流程阻塞：用户基本使用流程走不通、横屏主界面无法进入或关键交互失效 | P0 |
| R2 | 竖屏功能移植横屏后缺失或不可用（等价可用性不达标） | P0 |
| R3 | 各端联调主链路不通（设备端 / 移动端 / 手环端数据链路断裂） | P0 |
| R4 | 数据安全（敏感信息明文、越权访问、数据泄露） | P1（保底） |
| R5 | AI 数据准确性失准、设备监控灵敏度不达标 | P1 |
| R6 | 横屏 UI 显示缺陷但不影响主流程（控件遮挡、溢出、截断） | P2 |
| R7 | 布局美观 / 旋转后布局 / 横屏响应式 / Android·iOS 版本兼容 / 认证标准性能 | P3 |

## 四、各级别详细定义（范围 / 执行 / 评审 / 示例）

### 🔴 P0 — 可行性/概念性测试级
- **范围**：横屏版主流程功能，包括用户基本使用流程、横屏主界面与关键交互；竖屏功能移植到横屏后的等价可用性验证；各端（设备端 / 移动端 / 手环端）联调测试。
- **执行**：每次构建 / 每次提测必跑；CI 门禁纳入；任一失败阻断发布（一票否决）。
- **评审**：纳入发布准入清单，由测试经理 + 产品负责人双签。
- **示例**：横屏主界面加载并进入基本使用流程；横屏下开始/暂停/结束一次训练并完成保存；竖屏登录/训练控制移植横屏后功能等价可用；设备-移动端-手环端联调数据链路贯通。

### 🟠 P1 — 主流程必测级
- **范围**：按主流程步骤逐步拆解、必须执行的功能（依据横屏 UI 流程图编写用例）；等价类相关功能（含异常执行场景）；横屏布局与适配相关功能；AI 数据准确性；设备监控灵敏度；数据安全。
- **执行**：每轮主测试（SIT / 回归主集）必覆盖；允许极少数经评审的跳过并登记风险。
- **评审**：迭代评审会回顾覆盖与缺陷。
- **示例**：主流程各步骤节点（训练页→数据页→总结页）逐步功能验证；配速/心率输入的等价类与异常场景（非法值、中断恢复）；横屏布局下关键区域适配；AI 语音意图识别准确性与配速建议准确性；设备监控（心率/配速采样）灵敏度；敏感数据加密存储与越权访问防护。

### 🔵 P2 — 显示完整性级
- **范围**：横屏界面 UI 显示完整性；不影响主流程的基本功能，例如横屏下控件不遮挡、不溢出。
- **执行**：常规迭代覆盖；大版本回归纳入，小版本可抽样。
- **示例**：横屏下按钮/卡片不被遮挡、内容不溢出屏幕边界；长文本不截断关键信息；弹窗完整展示；非主流程页面（设置二级页）显示完整。

### ⚪ P3 — 美观与兼容级
- **范围**：UI 显示正确性与整体布局美观性（横屏下文字、Logo、图片、按钮、链接等显示是否正确，旋转后布局是否正确）；UI 整体布局美观性评估、横屏响应式；设备与系统版本兼容性（Android 与 iOS）；产品认证标准性能测试。
- **执行**：全量轮次或探索性测试按需覆盖，不计入发布门禁。
- **示例**：文字/Logo/图片/按钮/链接显示正确无变形；横竖屏旋转后布局正确重排；横屏响应式断点适配；Android 与 iOS 各系统版本兼容；按产品认证标准执行性能测试（帧率、启动耗时、功耗）。

## 八、分级 SOP 与维护

1. **初评**：作者按五维模型打分 → 套用映射表得初步级。
2. **硬规则校验**：逐条比对 R1~R7，命中取硬规则级（覆盖评分）。
3. **标注**：在模板「测试优先级」列填 P0~P3，备注依据（规则号或分数）。
4. **评审**：测试经理组织优先级评审会，重点复核 P0/P1。
5. **AI 优先级复核**：按既定规则对全库做一致性扫描，标记异常（如 P3 命中数据安全、P0 缺依据），人工确认。
6. **入库**：随用例库版本提交，纳入对应执行轮次集合。

- **升降级**：P3 连续 3 轮发现有效缺陷 → 升 P2；P0 长期零缺陷且业务降级 → 可降 P1（需评审）。
- **执行轮次**：冒烟/可行性验证=P0；主测试 SIT=P0+P1；回归=P0+P1+抽样P2；全量/探索=P0~P3。

## 九、速查卡

- 横屏主流程阻塞 / 竖屏移植不等价 / 各端联调不通 → **P0**
- 主流程必测功能 / 等价类异常 / 横屏布局适配 / AI 数据准确性 / 监控灵敏度 / 数据安全 → **P1**
- UI 显示完整性（不遮挡不溢出）/ 不影响主流程的基本功能 → **P2**
- 美观 / 旋转布局 / 横屏响应式 / Android·iOS 兼容 / 认证性能 → **P3**
- 拿不准：失败会不会阻断横屏主流程？会 → P0；不影响主流程但影响观感 → P2/P3。
