# 优先级分级策略（P0 / P1 / P2 / P3）

本文件为 `testcase-generator` 提供 **P0–P3** 四级优先级口径，是优先级分级的**唯一权威来源**。全技能统一采用此四级——**不再使用 P1–P4 体系，无 P4**；生成用例时 `priority` 字段仅可取 `P0` / `P1` / `P2` / `P3`，不得出现 P4 或其它分级。

## 一、分级总览（三色区分）

| 级别 | 颜色 | 定义 | 执行要求 | 占比建议 |
|------|------|------|----------|----------|
| **P0** | 🔴 红 | 核心链路 / 冒烟 / 安全合规 / 数据正确性 | 每次构建必跑，100% 通过方可发布（一票否决） | 10%~15% |
| **P1** | 🟠 橙 | 重要功能 / 高频场景 / 主流兼容性 | 每轮主测试必覆盖 | 25%~35% |
| **P2** | 🔵 蓝 | 一般功能 / 次要场景 / 低频兼容 | 常规迭代覆盖，回归可选 | 35%~45% |
| **P3** | ⚪ 灰 | 边缘场景 / 极端边界 / 探索性 | 全量或按需覆盖，不计入发布门禁 | 10%~20% |

## 二、五维评分模型（定量定级）

对每条候选用例，5 个维度各打 1~5 分，加权求和（满分 25）映射优先级：

| 维度 | 含义 | 5 分 | 1 分 |
|------|------|------|------|
| D1 业务重要性 | 用户主路径 / 商业核心 | 核心链路 | 极边缘配置 |
| D2 用户影响 | 失败的可感知与严重程度 | 数据丢失/安全事故 | 几乎无感可绕过 |
| D3 故障概率 | 历史缺陷与改动频率 | 高频改动/重灾区 | 极稳定少变更 |
| D4 修复成本 | 暴露后修复与回滚难度 | 需发版/固件硬件 | 前端文案小修 |
| D5 使用频率 | 真实用户触发频次 | 每次必达 | 极少触发 |

加权建议：D1×1.2、D2×1.2、D3×1.0、D4×0.8、D5×0.8。

**风险总分 → 优先级**：≥20 → P0；14~19 → P1；8~13 → P2；<8 → P3。
**保底规则**：安全质量属性与数据正确性用例，即便总分低也**保底 P1**；涉及人身安全/隐私泄露直接 **P0**。

## 三、硬规则决策表（命中即定级，高于评分）

| # | 规则 | 定级 |
|---|------|------|
| R1 | 阻塞主流程、设备/App 无法进入可用状态 | P0 |
| R2 | 人身安全、隐私泄露、支付资损、固件变砖（OTA 失败） | P0 |
| R3 | 校准结果错误导致训练数据失真（配速/心率区间、S1~S4 判定） | P0 |
| R4 | 核心冒烟用例（启动→登录→开始训练→结束保存） | P0 |
| R5 | 安全质量属性用例（越权、注入、敏感信息明文） | P1（保底） |
| R6 | 主流兼容性（主流机型/系统/手环） | P1 |
| R7 | 次要兼容、低频场景、极端边界 | P2 / P3 |

## 四、各级别详细定义（范围 / 执行 / 评审 / 示例）

### 🔴 P0 — 核心必保级
- **范围**：冒烟用例集、核心链路、安全合规红线、数据正确性、固件可用性的「一票否决」项。
- **执行**：每次构建 / 每次提测必跑；CI 门禁纳入；任一失败阻断发布。
- **评审**：纳入发布准入清单，由测试经理 + 产品负责人双签。
- **示例**：登录成功进入主页；开始/暂停/结束一次训练并正确落库；C00 校准 20 秒自动判定与锚点提取正确；OTA 升级不导致设备变砖；心率区间与配速区间计算正确。

### 🟠 P1 — 重要功能级
- **范围**：重要业务功能、高频用户场景、主流兼容性、安全属性、易用性主路径。
- **执行**：每轮主测试（SIT / 回归主集）必覆盖；允许极少数经评审的跳过并登记风险。
- **评审**：迭代评审会回顾覆盖与缺陷。
- **示例**：语音播报开关与多场景播报；AI Coach Lite 意图识别（确定性规则 + 关键词命中 + 固定问答双表）；个人中心数据同步；Apple Watch 与跑步机心率联合显示；主流机型蓝牙配对手环。

### 🔵 P2 — 一般功能级
- **范围**：一般功能、次要场景、低频兼容、部分性能/可靠边界。
- **执行**：常规迭代覆盖；大版本回归纳入，小版本可抽样。
- **示例**：非主流手环型号兼容；训练历史筛选排序；设置项非核心开关；弱网下的非核心提示文案。

### ⚪ P3 — 边缘探索级
- **范围**：极端边界、探索性、极低频配置、纯体验细节。
- **执行**：全量轮次或探索性测试按需覆盖，不计入发布门禁。
- **示例**：超长昵称/特殊字符；连续 100 次快速切歌；极端温度下的 IMU 漂移展示；已废弃入口的兜底。

## 五、与六类质量属性映射

| 质量属性 | 典型 P0 | 典型 P1 | 典型 P2/P3 |
|----------|---------|---------|------------|
| 功能 | 核心链路 | 重要功能 | 边缘功能 |
| 安全 | 隐私泄露/越权 | 敏感信息展示 | 防御性冗余 |
| 可靠 | 训练中断/数据丢失 | 重连/恢复 | 偶发抖动 |
| 易用 | — | 引导主路径 | 文案细节 |
| 兼容 | — | 主流机型/系统 | 冷门设备 |
| 性能效率 | 卡死/超时阻塞 | 响应达标 | 边缘劣化 |

## 六、与各端映射（设备/移动/手环）

| 端 | P0 关注点 | P1 关注点 | P2/P3 关注点 |
|----|-----------|-----------|--------------|
| 设备端 | 启动、训练主控、OTA、校准、I2C/BLE | 语音播报、显示、IMU | 极端硬件边界 |

## 八、分级 SOP 与维护

1. **初评**：作者按五维模型打分 → 套用映射表得初步级。
2. **硬规则校验**：逐条比对 R1~R7，命中取硬规则级（覆盖评分）。
3. **标注**：在模板「测试优先级」列填 P0~P3，备注依据（规则号或分数）。
4. **评审**：测试经理组织优先级评审会，重点复核 P0/P1。
5. **AI 优先级复核**：按既定规则对全库做一致性扫描，标记异常（如 P3 命中安全属性、P0 缺依据），人工确认。
6. **入库**：随用例库版本提交，纳入对应执行轮次集合。

- **升降级**：P3 连续 3 轮发现有效缺陷 → 升 P2；P0 长期零缺陷且业务降级 → 可降 P1（需评审）。
- **执行轮次**：冒烟=P0；主测试 SIT=P0+P1；回归=P0+P1+抽样P2；全量/探索=P0~P3。

## 九、速查卡

- 阻塞 / 安全 / 数据错 / 固件砖 → **P0**
- 重要功能 / 高频 / 主流兼容 / 安全属性 → **P1**
- 一般功能 / 次要场景 → **P2**
- 边缘 / 极端边界 / 探索 → **P3**
- 拿不准：用户能不能绕过？不能 → 至少 P1；能且极少触发 → P3。
