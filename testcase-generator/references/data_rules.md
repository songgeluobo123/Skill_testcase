# 数据规则库、优先级模型与评分维度

本文件为 testcase-generator 技能提供可复用的"硬约束"：测试数据校验规则、优先级划分模型、
以及 0–100 质量评分 rubric。生成用例与校验时优先遵守本文件中的规则。

---

## 1. 数据-规则映射库（示例，可按项目扩展）

生成测试数据时严格遵循以下规则。可把项目真实的字段约束补充进此库。

```json
{
  "手机号":   { "格式": "11 位数字", "前缀": ["138", "139"] },
  "订单金额": { "类型": "number", "范围": "≥ 0.01", "精度": "2 位小数" },
  "用户等级": { "枚举": ["普通", "VIP", "SVIP"] }
}
```

规则要点：

- **手机号**：11 位数字，常见前缀 138/139 等；不得出现 "12345"（长度不足）或含字母。
- **订单金额**：数值型，≥ 0.01，保留 2 位小数；不得出现负数 "-100" 或 0。
- **用户等级**：只能取枚举值 {普通, VIP, SVIP}；不得出现未定义等级。
- **动态关联**：有依赖关系的数据需生成关联链。如"用户 ID = U123" → 订单号 "ORD-U123-xxx"。
- **合法性预校验**：对照系统元数据（如 Swagger 参数规则）。例：用户名长度 3–10 位，
  则过滤 "ab"（2 位）和 "abcdefghijk"（11 位）。

> 扩展方式：把项目的真实字段、格式、范围、枚举补充进上表；用例生成与 `score_testcases.py`
> 都会据此校验测试数据有效性。

## 2. 优先级划分模型（业务影响 × 用户频率）

| 维度 | 取值 |
|---|---|
| 业务影响度 | 高 / 中 / 低 |
| 用户频率 | 高频 / 低频 |

映射结果（采用 P1–P4，P1 最高，与 `case_design.md` 口径一致）：

| 优先级 | 业务影响 | 用户频率 | 示例 |
|---|---|---|---|
| **P1** | 高 | 高频 | 支付成功后订单生成、登录成功 |
| **P2** | 高 | 低频 | 年付会员续费、优惠券核销 |
| **P3** | 低 | 高频 | 修改个人头像、列表筛选 |
| **P4** | 低 | 低频 | 界面字体颜色、兼容性探索 |

要点：核心场景（高业务影响）优先，P1 为冒烟 / 核心正向；不得将 P1 与 P4 颠倒；尽量避免冗余用例。

### 2.1 P0–P3 优先级模型（项目模板采用 P0–P3 时使用）

部分项目用例模板实际采用 P0–P3 四级（如 AI 魔镜跑步机测试套件）。此时以
`references/priority_p0_p3.md` 为准，采用「五维评分（D1–D5）× 硬规则（R1–R7）」定级，
与上面的 P1–P4 业务影响 × 用户频率模型等价，对应关系如下：

| P0–P3 | P1–P4 | 含义 |
|---|---|---|
| **P0** | P1 | 核心/冒烟/一票否决（安全、数据正确、固件可用） |
| **P1** | P2 | 重要功能/高频/主流兼容 |
| **P2** | P3 | 一般功能/次要场景 |
| **P3** | P4 | 边缘/探索/极端边界 |

> 归一规则：脚本导出或跨项目比对时，P0→P1、P1→P2、P2→P3、P3→P4 自动映射，保证两套口径互通。
> P0–P3 的保底与硬规则（安全属性保底 P1、人身安全/固件变砖直接 P0）优先级高于评分结果。

## 3. 质量评分维度（0–100，权重合计 100%）

| 维度 | 权重 | 考察内容 |
|---|---|---|
| 覆盖完整性 | 30% | 是否覆盖所有显性/隐性需求、业务规则、异常场景 |
| 准确性 | 25% | 步骤与预期结果是否符合业务逻辑，无矛盾错误 |
| 可执行性 | 25% | 步骤清晰无歧义、前置条件完整、测试数据有效 |
| 优先级合理性 | 20% | 优先级与业务影响匹配，无冗余/颠倒 |

**评级与动作：**

- **≥ 70 分**：通过，可交付。
- **< 70 分**：不通过，返回对应前序阶段重生成（如覆盖不足 → 场景挖掘阶段补充场景；
  数据无效 → 数据生成阶段重生成；步骤歧义 → 用例编排阶段重写）。

`scripts/score_testcases.py` 提供结构化的首轮自动评分（覆盖字段完整性、数据规则、优先级字段等），
作为人工/模型终审的辅助。
