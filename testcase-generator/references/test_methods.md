# 六种黑盒测试设计方法（有序叠加）

不是随机调用，而是**有顺序地叠加**。最终用例集是一个有结构、有层次的整体，而不是需求的翻译稿。

**核心观点：测试设计不是翻译需求，而是构造有效验证。**

---

## 1. 等价类划分（Equivalence Partitioning）

把所有输入划分成**有效区间**和**无效区间**，不遗漏、不重叠。

- **有效等价类**：合法输入（应被系统接受）。
- **无效等价类**：格式错误、越界、空值、非法类型（应被系统拒绝或纠正）。
- **用法**：先枚举每个字段的有效 / 无效类，再为每个类至少设计 1 条用例。
- **例**：手机号字段 → 有效类 {11 位合法号}；无效类 {10 位、12 位、含字母、空、非 1 开头}。

## 2. 边界值分析（Boundary Value Analysis）

对数值 / 长度字段，计算**上点、离点、内点**，而不是靠感觉"试试边界"。

- **规则**：区间 `[a, b]` 取 `a-1, a, a+1, b-1, b, b+1`（视开闭区间调整）。
- **例**：限购 5 件 → 4 / 5 / 6；昵称长度 3–10 → 2 / 3 / 10 / 11。
- **注意**：边界值应与等价类的"无效类"呼应，用预审去重避免重复覆盖同一无效点。

## 3. 场景法（Scenario Method）

梳理**基本流、备选流、异常流**，业务主线和每一条分支都要覆盖。

- **基本流**：成功主路径（一次走通）。
- **备选流**：可恢复的分支（如验证码输错 1 次后重试成功）。
- **异常流**：中断 / 失败路径（网络断开、权限不足、会话过期）。
- **用法**：画出状态 / 流程图，每条边至少 1 条用例；用 `multimodal.md` 从流程图截图直接导出。

## 4. 状态迁移法（State Transition）

识别业务对象的所有状态，定义状态转换条件和触发事件，验证合法转换和非法转换。

- **适用**：订单状态、审批流程、任务生命周期、设备连接状态等。
- **用法**：列出状态集合与转换表；为每条合法转换设计 1 条用例，为典型非法转换（如"已取消→已支付"）设计否定用例。
- **例**：骑行中不可切换模式 → 状态 `riding` 下 `switch_mode` 事件应被拒绝（非法转换用例）。

## 5. 判定表法（Decision Table）

适用于**多条件组合**的业务规则：列出所有条件桩和动作桩，生成条件组合并确定预期动作。

- **适用**：权限控制、费用计算、规则引擎、促销叠加。
- **用法**：条件 × 取值穷举 → 化简无关列 → 每列一条用例。
- **例**：会员等级（普通/VIP）× 活动（有/无）× 优惠券（有/无）→ 实付金额与权益动作组合。

## 6. 正交分析法（Orthogonal Array）

从全面组合中选取**代表性组合**，减少用例数量同时保证覆盖率。

- **适用**：多条件筛选、配置组合测试、多参数表单。
- **用法**：用正交表 L_n 选取因子水平组合，覆盖每对因子至少同现一次。

---

## 叠加顺序（关键）

```
等价类划分 → 边界值分析 → 场景法 → 状态迁移法 → 判定表法 → 正交分析法
 (输入维度)    (输入维度)   (流程维度)   (状态维度)    (组合维度)   (组合优化)
```

- 前两者保证**"输入维度"**覆盖（每个字段的有效 / 无效 / 边界）；
- 场景法 + 状态迁移法保证**"流程 / 状态维度"**覆盖（主线 + 分支 + 状态转换）；
- 判定表 + 正交分析保证**"多条件组合维度"**覆盖（组合不爆炸）；
- 错误推测作为高风险补漏仍可使用，记为第 7 类辅助方法。

## 在 Skill 中的落点

- 每条用例在 JSON 中用 `design_method` 字段记录所用方法（可多选，如 `["等价类划分","边界值分析"]`）。
- `scripts/prescreen.py` 第 4 项检查"每条用例是否关联 ≥1 种合法方法"，第 5 项检查"覆盖规则是否落在需求清单内"，保证**场景不脱离需求、方法不落空**。
- 合法方法集合：`等价类划分` / `边界值分析` / `场景法` / `状态迁移法` / `判定表法` / `正交分析法`（外加辅助 `错误推测`）。
