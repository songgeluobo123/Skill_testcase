# 记忆机制：越用越懂你

这是让 Skill 从"能用"变成"好用"的关键。第一次生成后，它会在项目里记下你的偏好与判断；用了几次后，生成质量会明显比第一次好——不是模型升级了，而是它记住了你的项目和习惯。

**核心观点：用了几次之后，生成质量会明显比第一次好，因为它记住了你的项目和你的习惯。**

---

## 记录位置

在**项目**的 `.workbuddy/memory/` 下创建 / 追加 `testcase_writer.md`。

- 每次触发 Skill 先**读**该文件；生成时把新判断**写回**（追加，不覆盖历史）。
- 该文件随项目走，团队共享同一份记忆。

## 记录内容

| 类别 | 记录什么 | 用途 |
| --- | --- | --- |
| 歧义判断 | 某模糊需求如何理解、怎么决断 | 下次类似描述直接复用，避免反复问 |
| 端类型 | 本项目是 PC / Web / APP / 小程序 | 下次不用重选，默认沿用 |
| 步骤粒度 | 偏细 / 偏粗，是否要展开到定位级 | 保持风格一致 |
| 历史漏测 | 哪类场景之前常漏（如并发、退款） | 本次自动补进去 |

## 文件格式建议

```markdown
## 歧义判断
- "支持多种登录方式" → 理解为 手机号 + 第三方，不含邮箱（2026-08-06）

## 端类型
- APP（iOS / Android）

## 步骤粒度
- 中等：步骤含元素定位，不展开到像素级

## 历史漏测
- 并发提交类场景之前常漏，本次已补
- 退款后优惠券返还未覆盖，已加 2 条用例
```

## 读取时机（对接六步工作流）

- 使用 `scripts/memory_io.py init --root <项目根>` 创建模板；后续用 `memory_io.py load` 读取。
- **Step 1 开头**：`load` 读端类型、历史漏测 → 直接套用，并预补已知常漏场景。
- **Step 2**：`load` 读歧义判断 → 遇到同类模糊描述直接复用结论。
- **Step 4**：`load` 读步骤粒度 → 统一步骤详略。
- **Step 6 结尾**：`memory_io.py record --category <...> --content <...>` 把本次新判断追加写回。

> 记忆只沉淀"决策与偏好"，不沉淀具体用例内容，避免文件膨胀、便于复用。
