# 等价类 / 边界值矩阵（Step 3.5 强制中间产物）

> **一句话**：矩阵是密度闸门唯一的燃料。没有矩阵，`--min-cases-per-rule 6` 只会逼出"同一条需求复制 6 遍"；有矩阵，6 条才各有其类、各有其界。
>
> **与其他文件的边界**：测试设计方法本身见 `test_methods.md`；用例字段与写法见 `case_design.md` / `output_format.md`；矩阵是"测什么"的清单，不重复定义"怎么写"。

---

## 一、为什么必须多这一步

预审第 11 项（需求密度）和 Step 3 的四类场景配额都只管**数量构成**，管不了"这 6 条是不是同一件事换个说法"。实测证据：

- 某真实库 196 条 / 47 需求，**33 条需求恰好 4 条（70%）**，模块级检查全绿；
- 其中 13 条标了「边界值分析」，**只有 3 条真有边界断言**（0%、0 km/h、最小值/最大值），其余 10 条是标签；
- 打开逐需求密度闸门后，缺口 83 条——但**这 83 条从哪来？**

答案只能是：**先把字段的等价类与边界点穷举出来**，用例才有地方长。不穷举就补，补出来的必然是薄壳。

## 二、格式：**一行一项**，不是一行一个字段

```markdown
| # | 字段 | 类型 | 取值域 | 类/边界点 | 类别 | 预期要点 | 覆盖 R-ID | 用例 ID |
|---|---|---|---|---|---|---|---|---|
| 1 | SOC | 数值(0–100%) | 0–100% | 1–99 | 有效类 | 展示真实 SOC 值与单位 | R-023 | TC-PWR-001 |
| 2 | SOC | 数值(0–100%) | 0–100% | 0 | 边界 | 展示 0%，不误判为缺失 | R-023 | TC-PWR-002 |
| 3 | SOC | 数值(0–100%) | 0–100% | 100 | 边界 | 应展示 100%，不得回绕为 0 | R-023 | TC-PWR-005 |
| 4 | SOC | 数值(0–100%) | 0–100% | 0xFF 无效码 | 无效类 | 显示电量暂不可用，不展示伪值 | R-023 | TC-PWR-003 |
```

**为什么不做"一行一个字段"**：字段级一行时，「有效类」列写成 `0 / 1–99 / 100`、「用例 ID」列写一串 ID，**无法判断哪个类被哪条用例消费**——只能退化成"这一行有 ID 就算覆盖"，这就是本技能在覆盖率评审里已经踩过的**假覆盖**（见 `coverage_audit.md`：模块名相同不等于覆盖）。一行一项才可判。

### 列定义

| 列 | 必填 | 说明 |
|---|---|---|
| `#` | 否 | 行号，便于评审引用 |
| **字段** | 是 | 被分析的数据项/参数/状态名，同一字段可跨多行 |
| **类型** | 是 | `数值 / 整数 / 枚举 / 布尔 / 字符串 / 日期 / 时间 / 金额 / 百分比 / 时长 / 版本号` 等；可带取值范围括号，lint 只看括号前 |
| **取值域** | 否 | 该字段的完整合法域（如 `0–100%`、`0/1/2/3/4/5`） |
| **类/边界点** | 是 | **一个**等价类或**一个**边界点（`1–99` / `0` / `100` / `0xFF` / `断连旧值`） |
| **类别** | 是 | 只认三值：`有效类` / `无效类` / `边界`（`边界值`、`边界点` 也接受） |
| **预期要点** | 是 | 这一项该断言什么：具体值 / 阈值 / 逐字文案。空着等于没说测什么 |
| **覆盖 R-ID** | 建议 | 服务哪条需求，分号分隔；填了就会与需求清单校验（查编造） |
| **用例 ID** | 是 | 消费这一项的用例，分号分隔。**为空即「未消费等价类」** |

## 三、lint 规则（`scripts/matrix_lint.py`）

| 代号 | 检查 | 级别 |
|---|---|---|
| **L1** | 表头必需列齐全（字段 / 类-边界点 / 类别 / 用例 ID） | 阻断（退出码 2） |
| **L1b** | 每行列数 ≥ 表头所需列数 | **阻断**——少一列会整体错位，静默误判比报错更危险 |
| **L2** | 数值/枚举类字段的边界点数 ≥ `--min-boundary`（默认 3） | 阻断 |
| **L3** | 每行「用例 ID」非空 | 阻断（未消费等价类） |
| **L3b** | 每行「预期要点」非空 | 告警 |
| **L4** | 「覆盖 R-ID」落在 `--requirement-rules` 清单内 | 阻断（查编造） |
| **L5** | 标 `[假设]` 的行占比 ≤ `--assume-max`（默认 30%） | 超限阻断，否则告警并单列 |
| **L6** | 字段类型在类型白名单内 | 告警（口径不统一） |
| **L7** | 同一字段内「类/边界点」不重复 | 告警（矩阵冗余） |
| **L8** | 每个数值/枚举字段至少有 1 行「无效类」 | 告警（非法取值是否漏测） |
| **L9** | `--cases`：矩阵引用的用例 ID 在用例库中真实存在 | 阻断（回指闭环） |

### `[假设]` 为什么不计入有效覆盖

无数据字典时，边界值只能靠推测。推测不是不能写，但**必须可识别**：行内任意位置写 `[假设]`，lint 会把该行从"边界点数""已消费"统计中剔除，并单列「假设行」清单交人确认。

这不是形式主义——见优化方案风险 R2：**为过一致性校验硬编边界数值，造出伪断言比不写更危险**。`[假设]` 行占比 >30% 即判"在为无依据的数据编边界"，直接阻断。

## 四、命令

```bash
# 基本（只看矩阵自身完整性）
python scripts/matrix_lint.py "test_output/{版本}/testpoint/等价类边界值矩阵.md"

# 推荐：同时校验需求非编造 + 用例回指真实存在
python scripts/matrix_lint.py 矩阵.md \
       --requirement-rules requirements.json \
       --cases test_cases.json \
       -o 矩阵lint报告.md

# 调门槛（字段少/简单项目）
python scripts/matrix_lint.py 矩阵.md --min-boundary 2 --assume-max 0.4
```

退出码：`0` 通过（可带告警）｜`1` 不达标｜`2` 输入或表头错误。

## 五、流程位置

```
Step 3 测试点  →  Step 3.5 矩阵（本文件 + matrix_lint.py）  →  Step 4 模板  →  Step 5 用例
                        ↓ lint 不通过
                    ❌ 不得进 Step 5
```

- **产物路径（强制）**：`test_output/{版本+需求名}/testpoint/等价类边界值矩阵.md`
- **未通过 lint 不得开始写用例**——否则写出来的用例没有来源，第 12 项（方法一致性）会成片判虚标。
- 矩阵与用例同版本归档；矩阵是「覆盖依据」，不随代码回滚（见优化方案 §5.3）。

## 六、与其它闸门的配合

| 闸门 | 矩阵给它什么 |
|---|---|
| 预审第 11 项（需求密度） | 每条需求的**可测项数**= 矩阵中该 R-ID 的行数。行数 < 6 就别指望写出 6 条真用例——先补需求或补字段，别硬凑 |
| 预审第 12 项（方法一致性） | 标「边界值分析」的用例必须回指矩阵里的边界行；没有矩阵就没有依据，这正是虚标的根源 |
| 覆盖率评审 | 矩阵行 ↔ 用例 ID 的对应关系就是**最小可核对的 RTM** |

## 七、真实样例（历史库回放，如实记录缺口）

对某 196 条库中 R-023 电量 / R-024 助力档位 / R-026 实时车速三组构矩阵（`skill_research/等价类边界值矩阵_样例_车辆信息.md`）：

```
字段 3 / 行 14 / 边界点 7 / 未消费等价类 5 / 阻断 7
SOC      边界点仅 2（0、100），缺 1；且 100 无用例
助力档位  边界点 3（0档/5档/6越界），三项全无用例
实时车速  边界点仅 2（0、99.9），缺 1；且 99.9 无用例
```

**结论**：这些正是密度缺口 83 条里"本该有却没有"的部分。矩阵一列出来，缺口从"感觉少了"变成"具体少哪一项"，补用例才有目标。

## 八、常见写法错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 每行少写一列（漏「类/边界点」） | 类别、预期、用例 ID 整体错位，lint 会把预期当类别 | L1b 会拦住并报"列数不足"，补齐即可 |
| 一行塞多个点：`0、100、101` | 边界点计数虚高，未消费判定失效 | 拆成三行，每行一个点 |
| 「取值域」写成该行的点（如把 `1–99` 填在取值域） | 「类/边界点」为空，L1b/L0 报错 | 取值域填完整合法域，类/边界点填**这一行** |
| 边界点写成区间：`1–99 之外` | 无法计数、无法回指 | 写成具体值：`0`、`100`、`101`、`-1` |
| 用例 ID 填了自己臆想的编号 | L9 报"引用了不存在的用例" | 先写用例再回填，或留空让 L3 拦住 |
| 类型写成中文长句（`电量百分比，两位小数`） | 命中 L6 告警，边界点要求也会失效 | 类型只写 `数值` / `百分比`，细节放取值域 |
