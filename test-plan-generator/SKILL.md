# 测试计划生成器

基于一份**标准测试计划模板**生成测试计划文件。模板提炼自 EQI 智能健身魔镜跑步机 V1.0 测试计划，结构通用，适用于各类软硬件产品的测试计划编写。

## 默认模板（单一事实来源，勿直接改写）

- 模板文件：`C:/Users/Administrator/Desktop/测试计划/测试计划模板.docx`
- 改模板本身需用户显式要求；生成测试计划时永远**复制模板 -> 填写副本**，不动原模板。

## 触发场景

用户表达"写/生成/做/出一份测试计划""根据 PRD/需求出测试计划""帮我起草测试计划"等。

## 工作流程

1. **复制模板**：用 `tencent-local-office-edit` skill 的 `open_file` 打开模板（或复制其字节为新的 docx），保存为
   `《{{产品名称}}》产品{{版本号}}测试计划.docx`（路径与用户确认，默认放 `C:/Users/Administrator/Desktop/测试计划/`）。
2. **填写占位符**：逐项替换文档中的 `{{...}}` 占位符：
   - `{{产品名称}}` / `{{版本号}}`：产品与版本
   - `规范更新日志`：首行填本次创建日期、作者、说明
   - `背景` / `目标`：来自 PRD/需求/用户描述
   - `测试的方法` / `测试用例优先级判定(P0-P4)` / `测试执行的分类`：按项目实际测试策略填写（可沿用模板默认描述）
   - `软件版本` 表：填入各端固件/APP 版本号
   - `测试任务` 表：阶段流程可沿用 8 阶段骨架，时间填实际排期
   - `需要的测试资源`：按项目裁剪【必须】/【不必须】项
   - `测试执行时间`：计划开始日期
3. **校验**：确认所有 `{{...}}` 均已替换、表格无空白必填项、标题层级正确。
4. **交付**：`present_files` 呈现最终 docx，并提示可上传项目资料库 / 创建测试执行事项。

## 占位符约定

- `{{...}}` 为待填项；不适用的章节保留或删除均可。
- 模板已内置通用内容（测试方法、优先级定义、原则与规范、测试形式等），仅需替换产品相关项。

## 注意事项

- 涉及本地 Office 文件内容操作，先调用 `tencent-docs-routing` skill 确定工具路径，再用 `tencent-local-office-edit` 执行。
- 不要主动 `close_file`；保存用 `save_file` 即可。
